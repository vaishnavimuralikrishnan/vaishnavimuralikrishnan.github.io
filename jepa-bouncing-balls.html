What a Model Must Discard to Learn Physics

I trained two models to predict the next frame of a two-body elastic collision: one that predicts pixels directly, and one that compresses into a 64-dimensional latent space before predicting. The pixel model achieved a loss three orders of magnitude lower. It had learned almost nothing.

Task: Elastic collision dynamics, 64×64 pixels, no gravity Models: JEPA (1.9M params) vs. Pixel Transformer (2.7M params) Evaluation: 15-step open-loop rollout + latent intervention
01

The Environment

The experimental environment is deliberately small and controlled: a 64×64 pixel box containing two balls undergoing perfectly elastic collisions. Red ball: mass 2, radius 6. Blue ball: mass 1, radius 4. No gravity, no friction, no air resistance. The simulation is deterministic—given an initial state, the future is fixed. The dataset consists of 10,000 frames rendered from the physics simulation.

This simplicity is the point. The goal is not to build a production model, but to examine a precise question: what internal representation does a model construct to predict this dynamics, and what does that representation allow us to do?

02

Two Architectures

Pixel Transformer: No Bottleneck

This model patchifies each frame into 64 eight-by-eight patches, embeds them, applies six Transformer encoder layers, and unpatchifies back to pixels. There is no forced compression between input and output. Spatial resolution is preserved throughout, and every patch can attend to every other patch at each layer.

2,718,528 parameters. Embedding dimension: 192. Six encoder layers, eight attention heads.

JEPA: Forced Bottleneck

This model encodes each frame through four convolutional layers into a single 64-dimensional vector—a compression factor of 192 (from 12,288 raw pixels). A small MLP predictor advances that vector forward one step. The decoder reconstructs pixels from the predicted latent code afterward, only for the purpose of computing loss.

1,925,059 parameters. Latent dimension: 64. Momentum encoder with τ=0.99 for the JEPA variant.

The operative difference

The Transformer passes spatial detail straight through. The JEPA is forced, at every step, to route all scene information through a 64-number bottleneck. That constraint is the entire experiment.

03

Training & Loss

Both models trained for 30 epochs on the same data split (80% train, 20% val) with the same optimizer (AdamW, LR 1e-3, cosine annealing). Both minimized one-step prediction MSE between their output and the next frame.

Why this metric is deceptive

A one-step MSE this low is a warning sign. On a deterministic, high-frequency trajectory with fixed frame ordering, such a loss is consistent with the model having effectively memorized frame sequences rather than learned the underlying rule. The rollout below tests this directly.

04

Open-Loop Rollout

Training loss only requires predicting one step from ground truth context. To see what the models actually learned, I ran open-loop rollouts: feed the model's own prediction back in as the next input for 15 steps, with no ground-truth correction. This forces the model to cope with its own errors.

Interpreting the curves

The Transformer's near-flat error curve initially looks like success—but this is evidence of memorization, not stability. The model is not integrating a dynamics rule step by step; it is reproducing a pre-memorized sequence that it has already seen during training. The JEPA's error drifts upward, which is honest: it reflects a model advancing a dynamics rule forward and accumulating the small errors that come with that process.

05

Intervention on the Latent State

The clearest test of whether a model has built a manipulable state vs. memorized a trajectory is to alter the state mid-rollout and observe whether the model continues coherently. The procedure: run five steps normally, perturb the latent vector directly, then continue for five more steps without further intervention.

For JEPA, this is straightforward: add a large constant to all 64 latent dimensions (e.g., z += 2.0), decode, and observe whether the next predicted frame shows sensible movement relative to the new position.

For the Pixel Transformer, no such intervention is possible. There is no latent state to manipulate, only pixel inputs and outputs. The architecture has no mechanism for this kind of causal reasoning.

06

Discussion

The one-step training loss was the least informative statistic in this experiment. The Transformer's 0.00003 loss reflected not a better model of physics, but a model with no incentive to build one—no architectural pressure to discard irrelevant detail. The JEPA's higher loss was the cost of a bottleneck doing its job: 64 numbers cannot encode the arbitrary detail of 12,288 pixels, so the only frames the model can predict well are those that follow a rule.

This is where the result reads as physics rather than machine learning. A bottleneck is a modeling choice with consequences. Choosing to discard information deliberately, in the right place, is what left this model with a representation coherent enough to intervene on. The Transformer, with no such constraint, was free to memorize, and it did.

Neither model achieved a high linear probing R² for position (JEPA: 0.08–0.18). This suggests the latent space is not cleanly disentangled into semantic factors. But the intervention result—coherent behavior after latent perturbation—indicates the space contains structure that the model uses, even if we cannot easily read it off linearly. This is a limitation of the current analysis, not a refutation of the model's internal organization.
